# vento-realestate

A world-class ERP for Nigerian real estate developers: land & title, projects & construction, off-plan sales & CRM, finance (multi-entity, multi-currency), estate management, HR & payroll, compliance, documents & contracts, buyer portal, executive analytics. Top-of-the-line UX, nothing extra.

Read before working (map of all docs: `docs/README.md`):
- `docs/PRODUCT.md` — vision, personas, the ten modules and how they connect. Keep each module lean; don't add features outside it without asking.
- `docs/DOMAIN.md` — business vocabulary, statuses and rules.
- `docs/design/SCREENS.md` — every screen the product needs, the approved design board for it (in `docs/design/claude-design/`) and its build status. Tokens and the rules the designs set are in `docs/design/DESIGN-NOTES.md`. Update it whenever screens are added or changed; log deliberate departures from a design in `docs/design/CHANGES.md`.
- `docs/journeys/` — step-by-step user walkthroughs (start with `00-golden-thread.md`). Each journey is an e2e test and, once shipped, a help article.
- `docs/decisions/` — why the big choices were made. Don't reverse one without a new record.

## Stack
- **Monorepo:** pnpm workspaces + Turborepo — `apps/web`, `apps/api`, `packages/shared`
- **API:** Hono + oRPC on Node 24, contracts defined in `packages/shared` with zod v4
- **DB:** PostgreSQL + Drizzle ORM, migrations generated by drizzle-kit
- **Auth:** Better Auth with organizations (organization = the developer group; it contains one or more legal entities/SPVs)
- **Web:** Vite + React 19, TanStack Router (file-based), TanStack Query via the oRPC client, TanStack Table, react-hook-form + zod, shadcn/ui + Tailwind v4, Sonner, lucide, Recharts
- **Quality:** Biome (lint + format), Vitest, Playwright, GitHub Actions
- **Package manager:** pnpm only. Never npm or yarn.

## Commands
- `pnpm dev` — run web + api
- `pnpm db:up` — start local Postgres (Docker)
- `pnpm db:generate` / `pnpm db:migrate` — create / apply migrations
- `pnpm db:seed` — load the fictional golden-thread data (`docs/journeys/00-golden-thread.md`)
- `pnpm check` — Biome lint + format check
- `pnpm typecheck`, `pnpm test`, `pnpm e2e`
- Before any commit: `pnpm check && pnpm typecheck && pnpm test`

## Non-negotiables
1. **Organization isolation.** Every domain table has `organizationId` (FK, indexed, NOT NULL). Every query filters by the organization from the auth context, never from request input.
2. **Server-side authorization** per module × action in oRPC middleware. UI hiding is cosmetic only.
3. **Money** is `numeric(14,2)` in Postgres, a string in TS, and calculated with a decimal library. Never floats. Store currency (ISO 4217, default `NGN`) beside every amount; foreign amounts also store the FX rate, its source and date. Ledger entries are append-only and must balance per entity.
4. **One source of truth for types:** zod schemas in `packages/shared`. Never redeclare an API type in `apps/web`.
5. **Lists are server-paginated** with the shared `{ items, page, pageSize, total }` shape.
6. **Multi-table writes** run in one transaction.
7. **IDs** are UUID v7. Every table has `createdAt` / `updatedAt`. Soft delete via `archivedAt` for master data (parcels, projects, units, contacts); hard delete is blocked when history exists.
8. **Secrets** never enter the repo (it is public). Use `.env` (git-ignored) and document keys in `.env.example`.
9. **Dates:** store UTC `timestamptz`; instalment, permit and contract due dates are `date` (no time).
10. **Entity scoping:** finance, payroll, contracts and bank data belong to an entity (SPV). Permissions can be limited by entity or project.
11. **Statutory rules are data:** tax rates, payroll deductions, AML thresholds and similar rules live in versioned configuration with effective dates, never in code constants. Check current Nigerian law before changing them.
12. **Sensitive actions go through maker-checker** approval rules, and every change is written to the append-only audit trail.
13. **AI is optional.** Every AI feature is behind a per-organization flag and budget, has a manual path that works without it, and only *suggests*: nothing AI produces changes data until a person accepts it. Follow the `ai-features` skill.

## Code style
- TypeScript strict, no `any`, no non-null assertions without a comment.
- Small files and functions. Comment *why*, not *what*.
- `@/` imports inside apps. Named exports, except route files.
- UI uses design tokens only (no hex in components), works in dark mode and at 375px width.
- Tests sit next to the code (`x.test.ts`); e2e lives in `apps/web/e2e`.

## Workflow
Feature: **product-manager** specs (`docs/specs/`) → **architect** plans → **backend** + **frontend** build (**payments** for collections and receipts, **finance** for ledger, tax, payroll and reporting, **ai** for any AI feature) → **tester** covers → **reviewer** + **ui-designer** check → fix → docs → commit.
**Docs are part of done:** in the same commit, the journey matches the build (status `built`), `SCREENS.md`/`CHANGES.md` are current, new terms are in `DOMAIN.md`, hard-to-reverse choices have a decision record, shipped journeys have a help article in `docs/help/`, and user-visible changes are in `CHANGELOG.md`. Full list in `docs/README.md`.
Periodic and pre-release: **security** audits. Build, CI, deploys and monitoring: **devops**.
Project skills in `.claude/skills/` hold the step-by-step recipes (`add-module`, `add-list-page`, `db-migration`, `design-system`, `ux-writing`, `performance`, `paystack`, `nigeria-compliance`, `ai-features`, `testing-patterns`, `review-checklist`, `pre-commit-check`).
